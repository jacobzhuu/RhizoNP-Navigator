# Phase 2 Real PubMed Benchmark Annotation Policy

This document defines the human relevance labeling protocol and metric semantics for
`data/eval/phase2_real_pubmed_benchmark.json`. It must be read before annotation begins.

---

## Relevance Grades

| Grade | Meaning |
| --- | --- |
| **0** | Irrelevant — the paper does not address the benchmark query intent. |
| **1** | Partially relevant — the paper is related but not a direct answer. |
| **2** | Directly relevant — the paper clearly addresses the benchmark query intent. |

Reviewers record grades in the blind reviewer sheet only. Do not infer grades from
retrieval rank or system scores.

---

## Pooling Before Annotation

Candidate papers are generated by **pooled judging**, not a single retrieval system.

Default offline pool systems:

- `bm25`
- `dense_hash`
- `hybrid_hash`
- `hybrid_rerank_lexical`

For each benchmark query, the exporter unions each system's top-`k` paper-level hits
(default `k=20`), deduplicates by `(query_id, pmid)`, and records which systems
retrieved each PMID in a separate provenance sidecar.

Model-backed systems are **not** included in the default offline pool.

---

## Blind Annotation Artifacts

Two files are produced:

### 1. Blind reviewer sheet

Columns: `query_id`, `query_text`, `pmid`, `title`, `abstract`, `doi`, `grade`, `notes`

Must **not** contain: `retrieval_system`, `rank`, `score`, `category`, `source_url`

### 2. Provenance sidecar

Columns: `query_id`, `pmid`, `retrieval_system`, `rank`, `score`

Used after annotation to audit which systems surfaced each candidate. Not shown to
reviewers during grading.

---

## Label Import Rules

- One label per `(query_id, pmid)` pair.
- Duplicate labels for the same pair are rejected.
- PMIDs must exist in the ingested corpus snapshot.
- Grades must be exactly `0`, `1`, or `2`.
- Empty grade cells are skipped (unjudged).

Import accepts the blind reviewer CSV format.

---

## Unjudged Documents

**Policy:** Unjudged PMIDs are excluded from evaluation qrels.

- They are **not** automatically treated as irrelevant.
- They do **not** enter the recall denominator.
- Retrieved but unjudged PMIDs contribute **zero gain** to nDCG and do not count as
  hits for Recall/MRR.
- Unjudged PMIDs still **occupy rank positions** in nDCG discounting when they appear
  in the retrieved list.

This avoids silently penalizing systems for returning papers that were never reviewed.

---

## Metric Semantics

All real-benchmark metrics operate at **paper level** (PMID), aggregating chunk hits
by best score per paper.

### Primary threshold (Recall@k, MRR@k)

- Relevant set: judged PMIDs with **grade ≥ 1**
- Recall@k = |relevant ∩ top-k retrieved| / |relevant|
- MRR@k uses the first retrieved relevant PMID (grade ≥ 1)

### Strict threshold (sensitivity)

- Relevant set: judged PMIDs with **grade = 2** only
- Reported as `strict_recall_at_*` and `strict_mrr_at_*` in per-query metrics

### Graded nDCG@10

- Gain for a retrieved PMID = its judged grade (0, 1, or 2)
- Unjudged retrieved PMIDs contribute gain 0
- Ideal DCG uses the sorted judged positive grades for that query

---

## Duplicate Judgment Handling

- Import rejects duplicate `(query_id, pmid)` rows by default.
- If two reviewers disagree, resolve offline and import a single final label.

---

## Unknown PMID Handling

- Import rejects PMIDs not present in the ingested corpus by default.
- This prevents labels for papers outside the evaluation corpus.
